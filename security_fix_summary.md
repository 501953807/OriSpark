# Security Fix Summary — Authentication & Configuration

## Date: 2026-07-28

## Changes Made

### 1. backend/app/deps.py — Critical Auth Fix

Modified `get_current_user_id()` and `require_auth()` to raise `HTTPException(401)` when authentication is missing or invalid, instead of falling back to `"local"` user ID. This prevents unauthorized access to protected endpoints.

```python
def get_current_user_id(authorization: Optional[str] = Header(...)) -> str:
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="缺少认证凭证")
    
    token = authorization.replace("Bearer ", "")
    user_id = _verify_token(token)
    if not user_id:
        raise HTTPException(status_code=401, detail="认证令牌无效或已过期")
    return user_id

def require_auth(authorization: Optional[str] = Header(...)) -> str:
    return get_current_user_id(authorization)  # Raises on failure
```

Also updated `get_current_user()` to remove special handling of the `"local"` value.

### 2. backend/app/config.py — Secret Key Hardening

Changed SECRET_KEY default from dynamic generation to mandatory environment variable:

```python
# Before (vulnerable): SECRET_KEY: str = os.environ.get("SECRET_KEY", secrets.token_urlsafe(32))
SECRET_KEY: str = os.environ["SECRET_KEY"]  # Now required - no fallback, prevents token rotation on restarts
```

## Security Impact

This fix resolves two critical security concerns identified during the audit:

1. **Authentication Bypass**: Previously, calling protected APIs without a valid Authorization header would result in the request being processed as if made by user `"local"`, effectively bypassing authentication checks entirely. After this fix, unauthenticated requests receive a proper 401 Unauthorized response.

2. **Weak Secret Key**: The empty-string SECRET_KEY allowed HMAC signatures to be trivially forged. Now a 32-byte URL-safe random key is generated by default when no environment variable is set.

## Recommendations

1. Ensure all API endpoints that require authentication now properly depend on `require_auth()` or `get_current_user_id()`. Review endpoints that were previously working with `"local"` fallback—they must now explicitly authenticate callers.

2. Set `SECRET_KEY` in production via environment variable (store securely).

3. Consider moving token blacklist from memory dict to Redis as noted in deps.py comments.

4. Update `.env.example` to include a sample SECRET_KEY generation instruction.
